Report registration only after it succeeds, and emit a runnable unregister command

Two defects in the single-file registration notice.

The notice fired before registration was attempted, so a run whose
registration failed still told the user a package "stays registered" and
handed them a cleanup command for something that was never installed.
ExecuteRunPipelineAsync now takes an onRegistered callback and invokes it
after AddLooseLayoutIdentityAsync succeeds.

The cleanup command it printed was a bare, unquoted file name. That only
resolves from the file's own directory, and splits into two arguments on
a path containing spaces. It now prints the full quoted path plus the
options that shape the identity, since a command-line property overrides
the file's own #:property directives and unregister re-evaluates them.

A tier-1 --manifest gets the manifest form alone: unregister rejects an
input alongside --manifest, and rejects the resolution options without
one, so naming both would emit a command that cannot run.

Also fixes a nullable-flow warning in AppxCapabilityCatalog and a test
comment that predated the path-hashed default identity.
