Flag an empty find-api search against an index that failed to load

members, enums and check-property all qualify a negative answer when part of the
index could not be read -- the caller is told the result may be a false negative
and to run 'winapp find-api refresh'. Search never did.

Search is the one verb where this matters most and was hardest to notice: it
reports "found nothing" as a *success* with an empty result set, so it has no
error message to carry the qualification. A caller -- very often an agent about
to conclude an API does not exist and write around it -- could not distinguish
"no such API" from "the index is broken".

ApiSearchOutput now carries a "note" alongside its results, set only when the
search found nothing and a package's metadata failed to parse. Text output
prints it under the "No results found" line; --json exposes it as `note`.

The note stays rare on purpose: a search that found results is not a false
negative, and a complete index produces no note at all. Both are covered by
tests so it cannot decay into noise callers learn to ignore.
