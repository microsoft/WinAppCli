Resolve generic types written the way callers write them

Metadata stores a generic under the name it was compiled with --
Windows.Foundation.IAsyncOperation`1 -- and resolution compared against that
verbatim. Nobody types the arity suffix, so every generic in the Windows API
surface was unreachable:

  winapp find-api members IAsyncOperation    -> Type not found: IAsyncOperation
  winapp find-api members TypedEventHandler  -> Type not found: TypedEventHandler

Both now resolve, as do the fully-qualified form without the suffix and the C#
source form an agent writes when generating code (IAsyncOperation<StorageFile>,
including nested arguments such as Holder<Pair<A, B>>).

Arity is dropped only when the caller did not state one. Pair`2 and
Pair<A, B> still select that arity, and a bare "Pair" where both Pair`1 and
Pair`2 are indexed stays ambiguous and lists them -- answering with either would
be a confident answer about a type the caller did not ask for. A non-generic
type asked for with type arguments (Plain<Holder>) is still a miss.

The metadata form keeps working unchanged, so nothing that resolved before stops
resolving.

Verified live against samples/winui-app: IAsyncOperation, IAsyncOperation<StorageFile>,
TypedEventHandler and TypedEventHandler`2 all resolve; Button is unaffected.
